# 任务 16：修复干员伤害随机转移

## 任务目标
修复多个干员或多个战斗 field 的单位 ID/UID碰撞导致伤害被合并到另一名干员记录的问题。

## 修改文件
- `hud.js`
- 本地游戏 `public/mods/reality-hud/hud.js`
- 本地游戏根目录 `hud.js`

## 数据流变化
- 战场单位主键优先使用全局运行时 `id`，不再优先使用可能只在玩家棋盘内唯一的 `uid`。
- 没有运行时 ID 的快照使用 `playerId::uid` 命名空间。
- `m.field`、`b.start`、`b.ev` 和对象事件使用 `fieldId/battleId` 上下文隔离单位记录和攻击 FIFO。
- UID 匹配出现多个候选时返回空，不再随机取第一条记录。

## 已完成内容
- 修正 `damageUnitKey` 的 ID优先级和 UID命名空间。
- 增加 field/battle 上下文作用域到单位、来源、目标和攻击队列。
- 修正普通伤害、元素伤害、旧版 `atk → dmg`、状态事件和动态 `spawn` 的上下文传递。
- 已同步本地游戏 HUD 文件。

## 第一次代码审查
- 定位到原实现以 `uid` 为主键，多个玩家/单位的同值 UID 会覆盖同一记录。
- 检查了快照合并、单位查找和玩家归属；确认这是随机转移的直接原因。

## 修复内容
- 使用运行时 ID作为主键，并为无 ID 快照加入玩家命名空间。
- 增加 field/battle 作用域，避免本地 runner 多 field 事件复用同一单位记录。
- 对重复 UID采取保守的“无法唯一确认则不归属”策略。

## 第二次代码审查
- 确认显式来源、FIFO来源、目标查找和状态事件都使用同一 field 上下文。
- 确认新旧伤害格式、元素伤害、召唤物和敌人聚合不会绕过作用域。
- 确认快照仍能按玩家 UID合并，不会制造随机干员行。
- `git diff --check` 通过；按约束未运行自动测试。

## 补充审查与修复
- 复查结算/私人快照后发现其中的字符串 `id` 是干员定义 ID，不是战场运行时 ID；若按运行时 ID 建键，多名玩家使用同一干员仍会合并。
- 已将数字 `id`/显式 `unitId` 才视为运行时 ID；无 field 上下文的字符串 `id` 改按 `playerId::defId` 隔离，保留 `uid` 的玩家命名空间。
- 旧版伤害帧没有来源 ID 且同一目标存在多个待处理攻击时，停止使用 FIFO 猜测并归入未归类，避免再次随机转移。
- 第二次补充审查确认战场事件仍按 field/battle 上下文使用数字运行时 ID，快照与结算记录按玩家隔离；`git diff --check` 通过，未运行自动测试。

## 当前限制
- 完全没有来源 ID、field/battle 标识且存在重复 UID 的外部旧帧会被保守地视为无法唯一归属，不会随机分配。
- 旧版无来源帧若同一目标同时有多个攻击候选，也会显示为未归类；带来源 ID 的当前事件不受影响。
