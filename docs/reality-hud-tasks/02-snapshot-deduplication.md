# 任务 02：快照去重

## 任务目标
防止同一实时事件帧通过网络和本地 runner 重复到达，也防止不同战斗的快照高水位互相覆盖。

## 修改文件
- `hud.js`
- 本地游戏 `public/mods/reality-hud/hud.js`

## 数据流变化
- 为可识别的事件帧建立 `battleId/fieldId + gt + payload` 指纹。
- 同一帧重复到达时只处理一次。
- `unitStats/result` 快照的高水位键包含来源类型、战斗标识和回合号。
- 快照仍只在显示值低于快照值时补齐差额，不重复增加已经由事件计入的伤害。

## 已完成内容
- 增加 `seenFrames` 有界缓存，最多保留 512 个事件帧指纹。
- `resetDamageSession` 清理事件指纹缓存。
- 普通快照、结果快照和结果单位快照传递战斗标识。
- 快照高水位按来源/战斗/回合隔离。
- 本地游戏 HUD 文件已同步。

## 第一次代码审查
- 检查了帧指纹、快照键、事件和快照的差额补齐逻辑。
- 发现旧版无 `gt` 的消息会把消息类型字符串当作游戏时间，存在误去重风险。

## 修复内容
- `rememberDamageFrame` 只有在消息提供数值型 `gt` 时才启用去重。
- 没有明确游戏时间的旧格式消息继续正常处理。

## 第二次代码审查
- 确认同一 `battle/field + gt + payload` 的重复帧只处理一次。
- 确认合法的相同时间不同 payload 帧不会互相覆盖。
- 确认没有 `gt` 的旧帧不会被误丢失。
- 确认事件指纹缓存有 512 条上限并在重置对局时清空。
- 通过静态差异检查；按约束未运行测试。

## 当前限制
- 没有 `battleId/fieldId/gt` 的旧帧不做指纹去重，以避免误丢失合法事件。
- 尚未实现敌方伤害独立聚合。
