# 任务 13：敌人伤害分类

## 任务目标
修复敌人对干员或召唤物造成伤害时被归入“未归类伤害”的问题，让敌人窗口按敌人类型和伤害类型显示数据。

## 修改文件
- `hud.js`
- 本地游戏 `public/mods/reality-hud/hud.js`

## 数据流变化
- 带来源 ID 的伤害事件现在保留已登记的敌方单位记录。
- `spawn` 事件会先登记动态生成的敌人 `UnitInfo`，再解析同帧伤害事件。
- 已识别敌方来源的伤害进入 `recordEnemyDamage`，按 `defId` 聚合并记录受伤干员/召唤物。

## 已完成内容
- `sourceForDamage` 不再丢弃 `side: enemy` 的显式来源。
- 支持数组和对象形式的 `spawn` 事件。
- 保留旧事件格式和无来源兜底行为。
- 已同步本地游戏 HUD 文件。

## 第一次代码审查
- 检查了显式来源分支、敌方聚合入口和干员/玩家过滤。
- 发现动态生成敌人只通过 `spawn` 事件发送，HUD 未登记该事件，来源 ID 仍可能无法解析。

## 修复内容
- 在数组和对象事件解析器中增加 `spawn` 元数据登记。
- 确保同一事件帧中先处理生成事件，再处理伤害事件。

## 第二次代码审查
- 确认已登记敌方来源会进入 `recordEnemyDamage`，不会进入干员或玩家累计值。
- 确认动态敌人、召唤物和初始 `m.field` 单位都能使用统一来源解析。
- 确认旧版无来源事件仍保留原有未归类兜底，不会伪造敌人记录。
- `git diff --check` 通过；按约束未运行自动测试。

## 当前限制
- 事件既没有来源 ID、来源队列，也没有对应单位元数据时，仍无法精确判断敌人类型。
- 这类事件会继续保留为未归类或被目标侧过滤，避免误报敌人类型。
